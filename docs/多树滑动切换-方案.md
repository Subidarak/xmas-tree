# 多树 · 自动溢出 + 左右滑动查看 · 方案

> 需求：一棵树挂满 12 张，新照片自动放到下一棵；左右滑动在树之间切换。
> 状态：**仅方案，未改代码**。当时仍是单树、12 张封顶。
> 日期：2026-11-18

---

## 一、这个设计解决了什么

以前：12 张满了 → 返回「树上已经挂满啦」，活动就结束了。
现在：12 张满了 → 自动开第 2 棵，继续挂。

**12 张从"天花板"变成"一页"**，活动容量取决于树的数量，不再取决于单棵的渲染上限。

---

## 二、数据模型

`gifts.json` 每条记录加一个 `tree` 字段：

```json
{"id":"g7f3a2","name":"小王","msg":"圣诞快乐","file":"g7f3a2.jpg",
 "ts":1763380000000,"ip":"a1b2c3d4","tree":1}
```

- `tree` 从 1 开始，缺省按 1 处理（兼容没有 tree 字段的老数据）
- 前端按 tree 分组，一组一棵树

## 三、后端：谁决定挂到哪棵

服务端分配，客户端不参与（否则可以刷）。

```js
const PER_TREE  = 12;   // 每棵树上限，和前端 MAX_PHOTO 对齐
const MAX_TREES = 10;   // 最多几棵（10 × 12 = 120 张）

function pickTree() {
  var c = {};
  for (var i = 0; i < gifts.length; i++) {
    var t = gifts[i].tree || 1;
    c[t] = (c[t] || 0) + 1;
  }
  for (var t = 1; t <= MAX_TREES; t++) {
    if ((c[t] || 0) < PER_TREE) return t;   // 第一棵没满的
  }
  return 0;   // 全满
}
```

`POST /api/gift` 成功时多返回一个字段：

```json
{"ok":true,"id":"g7f3a2","tree":2,"total":13}
```

`GET /api/gifts` 每条带上 `tree`，并返回总棵数 `trees`。

### ⚠️ 并发坑（必须一起改）

现有代码是**先异步写图片、再 push 进数组**：

```js
fs.promises.writeFile(...).then(function () {
  gifts.push({...});        // ← push 在异步回调里
});
```

两个人同时提交时，两边的 `pickTree()` 都可能看到"树 1 还有空位"，于是都塞进树 1 → **超载**。

**改法**：把"查空位 + push"挪到同一个同步块里，再异步落盘；落盘失败就回滚。

```js
var tree = pickTree();
if (!tree) return send(res, 507, { ok:false, code:'FULL', msg:'树上已经挂满啦' });

var rec = { id: id, name: name, msg: msg, file: file, ts: Date.now(), ip: ip, tree: tree };
gifts.push(rec);                    // 先占位（同步，不会被插队）

fs.promises.writeFile(path, img).then(function () {
  return persist();
}).catch(function (e) {
  var i = gifts.indexOf(rec);
  if (i >= 0) gifts.splice(i, 1);   // 失败回滚
  console.error(e);
});
```

Node 单线程，同步块内不会被打断，这样就不会超载。

## 四、前端：一棵树 = 一个 seed

已有基础，不用重写：

```js
var seed = 20261225;
function rand() { seed = (seed * 1664525 + 1013904223) % 4294967296; return seed / 4294967296; }
// build() 用 rand() 撒 2000 个点
```

**每棵树的 seed 由一个基础值推出来**，保证形状各不相同、且每次打开都一样：

```js
function seedOf(treeIdx) {         // treeIdx 从 0 开始
  return 20261225 + treeIdx * 7919;  // 7919 是质数，打散相近 seed
}
```

配色也按索引轮换，让相邻两棵有区别：

```js
var PALETTES = [
  { greens:['#1fd47f','#12b76a','#2ae38c','#0f8f57','#3ef0a0'],
    lights:['#ffd479','#ffb35c','#8fe3ff','#ff7d6b','#fff3cd'] },   // 圣诞绿金
  { greens:['#6ec6ff','#4da3e0','#8fd8ff','#2f7fb8','#a8e4ff'],
    lights:['#ffe9a8','#fff6d0','#b8ecff','#ffd0a0','#ffffff'] }    // 新年蓝白
];
```

## 五、前端结构（方案 B 的扩展版）

保持现有全局变量，不重构。新增：

```js
var treeIdx = 0;            // 当前看第几棵
var photoCache = {};        // { treeIdx: [photoObj, ...] }
var known = {};             // 已渲染过的 id
```

### 切换函数

```js
function gotoTree(idx) {
  if (idx < 0 || idx >= treeCount) return;
  if (idx === treeIdx) return;

  photoCache[treeIdx] = photos.slice();   // 存当前这棵的

  treeIdx = idx;
  var pal = PALETTES[idx % PALETTES.length];
  seed = seedOf(idx);
  GREENS = pal.greens;  LIGHTS = pal.lights;
  sprites = {};                            // 配色变了，光晕缓存必须清

  pts.length = 0;
  build();                                 // 重撒 2000 个点（10–30ms）

  photos.length = 0;
  (photoCache[idx] || []).forEach(function (o) { photos.push(o); });
  reflow();

  state = 'open'; introOff = true;         // 直接开着，不重放开场
  updateDots();
}
```

⚠️ **`sprites` 必须清**。光晕是按颜色缓存的，不清会串色。

## 六、挂完自动跳到那一棵（关键体验）

后端把照片分到第 2 棵，但用户当前看的是第 1 棵——**挂完什么都看不见，会以为失败**。

必须在提交成功后跳过去：

```js
if (res.body.ok && res.body.tree) {
  var target = res.body.tree - 1;       // 后端从 1 开始
  if (target !== treeIdx) {
    gotoTree(target);
    flashTip('树上满了，放到第 ' + res.body.tree + ' 棵啦');
  }
  poll();
}
```

## 七、手势仲裁（同前，加一条）

现有：按下一律进旋转。

```
按下 → 待定
移动 12px 后定方向（只判一次）：
  水平为主 → SWIPE 模式，整页跟手平移
  其他     → ROTATE 模式（现有旋转逻辑）
松手：
  SWIPE 过屏宽 25% → 切到相邻那棵树
  SWIPE 没过       → 回弹
  没进入模式       → tap（点星星/照片）
```

⚠️ 只有一棵树时（`treeCount === 1`），滑动不做任何事，避免空滑。

## 九、边界情况

| 情况 | 处理 |
|---|---|
| 老数据没有 tree 字段 | 兜底当 tree=1 |
| 10 棵全满（120 张） | 返回 507「真的挂满啦」 |
| 只有 1 棵树 | 不显示圆点、滑动无反应 |
| 某棵树 0 张照片 | 正常显示空树，可挂 |
| 挂完跳到新树 | 提示「树上满了，放到第 N 棵啦」 |
| 别人挂了新树，我这边才知道 | 20 秒轮询时更新 `treeCount` |
| 切换时正在拖动 | 拖动中禁止切换，松手才判 |

## 十一、要你拍板

1. **最多几棵**：建议 **10 棵（120 张）**。够一个班用；太多的话圆点和内存都要再设计。
2. **第二棵及以后的样子**：我按"绿金 → 蓝白"交替，这样一眼能看出翻页了。要别的配色告诉我。
3. **切过去要不要重放开场**：建议**只有第 1 棵有开场**，其余直接开着（挂完跳过去还要再看一遍动画会很烦）。

## 十二、验收判据

1. 挂满 12 张后，第 13 张成功且 `tree=2`，页面自动跳到第 2 棵并看到自己那张
2. 左右滑动切换，树形不同，照片跟着切换
3. 切过去再切回来，照片还在，不用重新加载
4. 只有 1 棵时滑动无反应、无圆点
5. 手机上滑动手感：拖动 100px 切换，50px 回弹
6. 并发：同时两个请求，不会都落进同一棵导致 13 张
7. 帧率切完稳定后 ≥ 50fps
